# 自動開発フローの提案

席を外している間も開発が進み、必要なときだけスマホに通知が来る仕組みです。

```
        ┌──────────── 定期実行(例:毎朝・毎晩) ────────────┐
        │                                                    │
        ▼                                                    │
 ① GitHub の Issue(やることリスト)から次の課題を1つ選ぶ          │
        │                                                    │
        ▼                                                    │
 ② Claude がブランチを切って実装 → テスト → プルリクエスト作成     │
        │                                                    │
        ▼                                                    │
 ③ GitHub Actions(CI)が Mac 上でビルド・テスト・評価             │
        │ 失敗 → Claude が直して再プッシュ                        │
        ▼ 成功                                                │
 ④ 📱 スマホに通知:「レビュー待ちのプルリクエストがあります」      │
        │                                                    │
        ▼                                                    │
 ⑤ あなたがスマホで確認してマージ(ここだけ人の判断)──────────────┘
```

## 仕組みの中身

| 部品 | 役割 | 費用 |
|---|---|---|
| GitHub Issues | ワークストリームごとの「やること」を書いておく | 無料 |
| Claude のルーティン(定期実行) | 決まった時間に起きて、次の Issue を実装してプルリクエストを出す | Claude のプラン内 |
| GitHub Actions | プッシュのたびに Mac 上で自動テスト | 公開リポジトリなら無料。非公開は月の無料枠あり(Mac は消費が10倍) |
| 通知 | Claude アプリのプロジェクト通知、GitHub モバイルアプリの通知 | 無料 |

## 人が判断するところ

- プルリクエストのマージ(本番に入れるかどうか)
- 実機での聞き比べ(声の自然さは人の耳で判断)
- App Store への公開
